# 云书签接口表（S0 参考方案，与配套代码 v2 一致）

| 操作 | 方法 | URL | 成功时 | 失败时 |
|---|---|---|---|---|
| 查看列表 | GET | `/` | 200，列表页 | — |
| 打开添加表单 | GET | `/add` | 200，空表单 | — |
| 提交新书签 | POST | `/add` | 302，回到列表并提示成功 | 200，重新显示表单、提示错误、保留已填内容 |
| 打开编辑表单 | GET | `/edit/<id>` | 200，带当前值的表单 | 书签不存在：302 回到列表并提示 |
| 提交修改 | POST | `/edit/<id>` | 302，回到列表 | 同「提交新书签」 |
| 删除 | POST | `/delete/<id>` | 302，回到列表 | 书签不存在：302 并提示 |
| 健康检查 | GET | `/health` | 200，`{"status": "healthy"}` | — |

删除用 POST 而不用 DELETE：第2章的页面只有 HTML 表单，表单只能发 GET 和 POST。
第3章改用 JavaScript 发请求后，改为 `DELETE /api/bookmarks/<id>`。

## JSON 接口（第10讲）

给程序用，返回 JSON；与上面的页面共用同一张 bookmarks 表。错误一律返回 `{"error": 原因, "details": 补充信息或 null}`。

| 操作 | 方法 | URL | 成功时 | 失败时 |
|---|---|---|---|---|
| 查看列表 | GET | `/api/bookmarks`，可带 `?q=关键词` | 200，书签数组 | — |
| 查看一条 | GET | `/api/bookmarks/<id>` | 200，书签对象 | 404，书签不存在 |
| 创建 | POST | `/api/bookmarks`，请求体 `{"title": ..., "url": ...}` | 201，新书签对象 | 400，请求体不是 JSON，或验证失败（details 列出原因） |
| 修改 | PUT | `/api/bookmarks/<id>`，请求体同创建，两个字段都要给 | 200，修改后的书签对象 | 404，书签不存在；400，同创建 |
| 删除 | DELETE | `/api/bookmarks/<id>` | 204，无响应体 | 404，书签不存在 |
