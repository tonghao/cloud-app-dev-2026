## 本讲弄懂什么

本讲只弄懂一件事：**服务器上的数据，怎样变成浏览器里一张完整、改得动的页面**。PPT 第 20 页把它画成一次渲染的五步。下表的步名与那张图相同，多了两列：这一步暴露的错、在哪一段看到。

| 步 | 模块 | 做什么 | 这一步暴露的错 | 在哪一段看到 |
|---|---|---|---|---|
| ① 交出 | 一 | 视图函数调用 `render_template`，交出模板名和数据 | 模板文件找不到：500 | 第一段 |
| ② 套骨架 | 三 | 读 `index.html`，按 `extends` 套上 `base.html` | 块名对不上：内容消失，**不报错** | 第三段 |
| ③ 填内容 | 二 | 执行 `{{ }}`、`{% %}`：填值、循环、过滤、转义 | 变量名对不上：输出为空，**不报错**；标记没写完：500 | 第二段 |
| ④ 生成地址 | 四 | 模板里的 `url_for` 这时算出链接和样式表地址 | 函数名或参数不对：500 | 第四段 |
| ⑤ 浏览器 | 四 | 显示 HTML，再按 `<link>` 请求样式表 | 样式表不在：页面没有样式 | 第一段、第四段 |

注意两类错误：一类报错（500），一类不报错、只是内容空了。不报错的更难找：错常常犯在前一步（如 ① 交出时用错了名字），到后一步（③）才暴露。本讲的观察专门练它。

## 第二段　写出列表（模块二）

**目的**：在模板里用 `{% for %}` 循环输出每条书签，用 `{{ }}` 输出标题和网址，用过滤器 `length` 输出条数。原理见教材 2.5.3。

**步骤**：

1. 打开 `templates/index.html`。
2. 选中第 14 行 `<ul>` 到第 24 行 `<p>共 条书签</p>`，替换为下面的代码，保存：

   ```html
       <ul>
           {% for bm in bookmarks %}
           <li>
               <a href="{{ bm.url }}" target="_blank">{{ bm.title }}</a>
               <a href="/edit/{{ bm.id }}">编辑</a>
               <form method="post" action="/delete/{{ bm.id }}" style="display:inline">
                   <button>删除</button>
               </form>
           </li>
           {% else %}
           <li>还没有书签，<a href="/add">添加第一个</a>吧！</li>
           {% endfor %}
       </ul>
       <p>共 {{ bookmarks|length }} 条书签</p>
   ```

   说明：`{% for %}` 以 `{% endfor %}` 结束，漏写会报 `TemplateSyntaxError`。`{% else %}` 写在 for 里面，列表为空时显示。编辑、删除的地址第四段再改。

## 第四段　链接与样式表（模块四）

**目的**：用 `url_for` 按视图函数名生成地址，让链接跟着路由走；样式表地址也用 `url_for` 生成。做完提交 S2。原理见教材 2.4.5、2.5.5。

**步骤**：

1. 把 `index.html` 的全部内容换成下面的代码，保存：

   ```html
   {% extends "base.html" %}
   {% block title %}书签列表{% endblock %}
   {% block content %}
       <ul>
           {% for bm in bookmarks %}
           <li>
               <a href="{{ bm.url }}" target="_blank">{{ bm.title }}</a>
               <a href="{{ url_for('edit_bookmark', bookmark_id=bm.id) }}">编辑</a>
               <form method="post" action="{{ url_for('delete_bookmark', bookmark_id=bm.id) }}" style="display:inline">
                   <button>删除</button>
               </form>
           </li>
           {% else %}
           <li>还没有书签，<a href="{{ url_for('add_bookmark') }}">添加第一个</a>吧！</li>
           {% endfor %}
       </ul>
       <p>共 {{ bookmarks|length }} 条书签</p>
   {% endblock %}
   ```

   说明：带 `url_for` 的三处是本步改的：编辑链接、删除按钮、「添加第一个」。
2. 把 `base.html` 的全部内容换成下面的代码，保存：

   ```html
   <!DOCTYPE html>
   <html lang="zh-CN">
   <head>
       <meta charset="UTF-8">
       <title>{% block title %}云书签{% endblock %}</title>
       <link rel="stylesheet" href="{{ url_for('static', filename='css/style.css') }}">
   </head>
   <body>
       <h1>云书签</h1>
       <nav>
           <a href="{{ url_for('index') }}">首页</a> |
           <a href="{{ url_for('add_bookmark') }}">添加书签</a>
       </nav>
       {% block content %}{% endblock %}
   </body>
   </html>
   ```

   说明：带 `url_for` 的三处是本步改的：样式表、首页、添加书签。第一个参数是**视图函数名**，不是路径；动态部分用同名的关键字参数传入；静态文件的函数名固定写 `'static'`，`filename` 是相对 `static/` 的路径。
3. 刷新首页。
   结果：页面样式不变。
4. 把鼠标悬停在「编辑」上。
   结果：浏览器左下角显示的地址是 `/edit/1`。

**预测二　路由改名以后**

- **操作**：`app.py` 里把编辑路由的地址临时改成 `'/modify/<int:bookmark_id>'`，**函数名 `edit_bookmark` 不动**，保存。

## 拓展（课后完成）

**规则**：

- 拓展的路由写在 `app.py`「拓展写在这里」那一行与 `if __name__` 之间。新页面用新的模板文件，继承 `base.html`。
- 新页面用到的 HTML 标签，见 `HTML速查卡-页面.md`「写新页面时」一节。
- 不改主线：五条路由、`index.html`、`base.html` 都不动。下一讲要接着改主线，拓展放在单独的文件里，两边才不互相影响。
- 可以用 AI。第6讲开头抽查，被抽到的人做三件事中的一件：讲清拓展里的一行；当场改一处，先预测再运行；说出一处出错在五步中的哪一步暴露。
- 每项做完，打开首页确认主线没被改坏：三条书签、「共 3 条书签」、编辑链接是 `/edit/1`。

**E1　关于页**

- **任务**：新建 `templates/about.html`，继承 `base.html`，填 `title`、`content` 两个块。`/about` 返回这个页面。第4讲没有做 `/about` 的，新建这条路由。
- **提示**：照 `index.html` 的头三行写；视图函数照 `index` 用 `render_template`。
- **验证**：打开 `http://127.0.0.1:5000/about`，有「云书签」标题和导航；网页源代码里 `<title>` 是你填的标题。

**E2　条数页**

- **任务**：`/count` 显示「共 N 条书签」。超过 2 条显示「书签不少了」，否则显示「再加几条吧」。
- **提示**：`{% if 条件 %}……{% else %}……{% endif %}`，和 for 一样以结束标记收尾。条数可以在视图函数里用 `len(bookmarks)` 算好再传进模板，也可以在模板里用 `|length`。
- **验证**：打开 `/count`，看到「共 3 条书签」和「书签不少了」。在 `bookmarks` 里临时注释掉两条，刷新应看到「再加几条吧」，看完恢复。

**E3　详情页**

- **任务**：`/bookmark/<int:bookmark_id>` 显示一条书签的标题、网址和一个回首页的链接（用 `url_for`）。编号不存在时返回 404。
- **提示**：在视图函数里用 for 循环找 `id` 等于 `bookmark_id` 的那条书签，找到就 `render_template`。循环结束还没找到，返回 `'书签不存在', 404`（第4讲学过：返回元组，第二项是状态码）。
- **验证**：`curl -i http://127.0.0.1:5000/bookmark/1` 得到 200，内容含「Flask 官方文档」；`/bookmark/9`、`/bookmark/abc` 都得到 404。

**E4　编号列表**

- **任务**：`/numbered` 用循环变量 `loop.index` 给书签编号，再挑一个过滤器用在标题上。
- **提示**：`loop.index` 只能在 `{% for %}` 里面用，从 1 开始计数。中文标题加 `upper` 看不出变化，用「Flask 官方文档」验证。
- **验证**：打开 `/numbered`，每条前面有 1、2、3 编号，标题经过你选的过滤器处理。

**E5　自选页面**

- **任务**：自己设计一个继承 `base.html` 的新页面。`for`、`if` 至少用一个，过滤器至少一个，`url_for` 至少一处。
- **提示**：先写下三件事，再写代码：地址是什么；页面上显示什么；哪一处用 `url_for`。
- **验证**：自己写两步：打开哪个地址、应看到什么。

## 常见问题

| 段 | 现象 | 原因 | 处理 |
|---|---|---|---|
| 开工 | `Address already in use` 或 `Port 5000 is in use` | 另一个终端里已经在运行 `python app.py` | 在那个终端按 Ctrl+C，或直接用它。同一时间只运行一个。 |
| 开工 | `No module named 'flask'` | 虚拟环境未激活 | 在 `~/work/cloud-bookmark` 下执行 `source ../venv/bin/activate`。提示符前应出现 `(venv)`。 |
| 一 | `jinja2.exceptions.TemplateNotFound: index.html` | `templates` 不在 `app.py` 同一层，或名字拼错（如 `template`） | 执行 `ls ~/work/cloud-bookmark`，应同时看到 `app.py` 和 `templates`。不对就重做第一段第 1 步。 |
| 一 | 页面没有样式，终端里 `GET /static/css/style.css` 是 404 | `static` 没复制，或不在 `app.py` 同一层 | 重做第一段第 1 步。 |
| 一 | 页面上原样显示 `{{ bm.title }}` | 在文件管理器里双击打开了 HTML 文件，没有经过 Flask | 用浏览器访问 `http://127.0.0.1:5000`。 |
| 二 | 页面显示「还没有书签」「共 0 条书签」 | `render_template` 的参数名和模板里的变量名对不上 | 改成 `render_template('index.html', bookmarks=bookmarks)`。 |
| 二 | `TemplateSyntaxError: Unexpected end of template. Jinja was looking for the following tags: 'endfor' or 'else'` | 少写了 `{% endfor %}` | 在列表末尾补上。提示里是 `'endif'`、`'endblock'` 的，同理补 `{% endif %}`、`{% endblock %}`。 |
| 二 | 每次刷新都弹窗 | 预测一的第四条书签或 `\|safe` 没删 | 两处都删掉。 |
| 三 | 只剩标题和导航，列表不见了 | 子模板的块名和 `base.html` 里的不一致 | 两边都写 `content`。 |
| 三 | 子模板里新加的内容没显示 | 写在了 `{% block %}` 外面 | 子模板的内容全部放进块里。 |
| 三 | 页面最上面多出一些文字 | 写在了 `{% extends %}` 前面 | `{% extends %}` 放在第一行。 |
| 四 | `BuildError: Could not build url for endpoint 'edit'. Did you mean 'edit_bookmark' instead?` | `url_for` 的第一个参数写成了路径或别的名字 | 写视图函数名：`'edit_bookmark'`。 |
| 四 | `BuildError: ... Did you forget to specify values ['bookmark_id']?` | 动态路由的参数没有传 | 写成 `url_for('edit_bookmark', bookmark_id=bm.id)`。 |
| 四 | 点「编辑」得到 404 | 预测二临时改的路由地址忘了改回 | 改回 `/edit/<int:bookmark_id>`。执行 `grep -n modify app.py`，应无输出。 |
| 跟丢了 | 复制检查点后第4讲的拓展没了 | 整个复制了 `app.py` | 执行 `git diff app.py` 找到被删的拓展，复制回去；或执行 `git checkout app.py` 恢复到上次提交，再照第一段手改。 |
| 提交 | `git status` 里看到 `__pycache__` | `.gitignore` 缺失 | 执行 `printf 'venv/\n__pycache__/\n.env\n' > .gitignore`，再提交。 |
