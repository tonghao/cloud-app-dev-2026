## 本讲做完的样子

`app.py` 有 5 条路由，对应接口表的 7 个操作：

| 接口表中的操作 | 方法 | URL | 视图函数 |
|---|---|---|---|
| 查看列表 | GET | `/` | `index` |
| 打开添加表单、提交新书签 | GET、POST | `/add` | `add_bookmark` |
| 打开编辑表单、提交修改 | GET、POST | `/edit/<int:bookmark_id>` | `edit_bookmark` |
| 删除 | POST | `/delete/<int:bookmark_id>` | `delete_bookmark` |
| 健康检查 | GET | `/health` | `health` |

| 段 | 做什么 | 做完时 |
|---|---|---|
| 第一段　最小应用 | 写 `/` | 浏览器显示「书签列表」（检查点 S1a） |
| 第二段　添加与编辑 | 写 `/add`、`/edit` | `/edit/abc` 得到 404（检查点 S1b） |
| 第三段　删除与健康检查 | 写 `/delete`、`/health`，提交 | `/delete/1` 得到 405，已提交（检查点 S1） |

## 本讲弄懂什么

本讲只弄懂一件事：**Flask 怎样处理一个请求**。PPT 第 5 页把它画成三步（教材 2.3.4）。下表的步名与那张图相同，多了两列：这一步暴露的错、在哪一段看到。

| 步 | Flask 做什么 | 这一步暴露的错 | 在哪一段看到 |
|---|---|---|---|
| ① 匹配路由 | 按请求的路径和方法查映射表，找一条规则 | 路径对不上：404；路径对上、方法不对：405 | 第二段、第三段 |
| ② 调用视图函数 | 调用找到的函数，URL 里的值作为参数传入 | 函数出错：500 | 第一段、第二段 |
| ③ 包装成响应 | 按返回值的类型，补上状态码和 `Content-Type` | — | 第三段 |

每段的预测都在问：请求停在了哪一步，为什么。

## 第一段　最小应用

**目的**：运行第一个 Flask 应用。原理见教材 2.3.3、2.3.4。

**步骤**：

1. 新建文件 `app.py`。
2. 输入下面的代码，保存：

```python
from flask import Flask

app = Flask(__name__)          # ① 应用实例


@app.route('/')                # ② 路由：把 / 登记给下面的函数
def index():                   # ③ 视图函数：返回值就是响应内容
    return '书签列表'


if __name__ == '__main__':     # ④ 直接运行本文件时才启动开发服务器
    app.run(debug=True)
```

3. 在终端 1 执行 `python app.py`。
4. 在浏览器打开 `http://127.0.0.1:5000`。

请求停在 ② 调用视图函数：路由匹配成功，函数执行时出错。

## 第二段　添加与编辑

**目的**：一个地址处理 GET 和 POST 两种请求；从 URL 里取出编号。原理见教材 2.4.3、2.4.4。

注意：新路由一律写在 `if __name__ == '__main__':` 的上面。写在下面的路由不生效，访问得到 404。

**步骤**：

1. 把第 1 行改成 `from flask import Flask, request`。
2. 在 `index` 函数下面加入下面的代码，保存：

```python
@app.route('/add', methods=['GET', 'POST'])
def add_bookmark():
    if request.method == 'POST':
        return '收到新书签'
    return '添加书签的表单'


@app.route('/edit/<int:bookmark_id>', methods=['GET', 'POST'])
def edit_bookmark(bookmark_id):
    if request.method == 'POST':
        return f'收到对书签 {bookmark_id} 的修改'
    return f'编辑书签 {bookmark_id} 的表单'
```

3. 在浏览器打开 `http://127.0.0.1:5000/add`。
   结果：显示「添加书签的表单」。

   说明：浏览器地址栏只能发 GET 请求。下一步测 POST 请求，改用 `curl -X POST`。
4. 在终端 2 执行 `curl -i -X POST http://127.0.0.1:5000/add`。
   结果：显示「收到新书签」。

**预测一　编辑地址的状态码**

  curl -i http://127.0.0.1:5000/edit/abc
  curl -i http://127.0.0.1:5000/Edit/7

## 拓展

**规则**：

- 拓展写在 `app.py` 里「拓展写在这里」那一行与 `if __name__` 之间。
- 不改上面五条路由。后面几讲要接着改这五条路由，拓展放在单独的区域，两边才不互相影响。
- 可以用 AI。第5讲开头抽查，被抽到的人做三件事中的一件：讲清拓展里的一行；当场改一处，先预测再运行；说出一个状态码的含义。
