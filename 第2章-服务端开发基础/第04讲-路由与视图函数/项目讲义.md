### 第一段　最小应用（同步点 S1a）

**目的**：写出并运行第一个 Flask 应用，认出它的四个组成部分；看一次调试模式的错误页。

新建 `app.py`：

```python
from flask import Flask

app = Flask(__name__)          # ① 应用实例


@app.route('/')                # ② 路由：把 / 登记给下面的函数
def index():                   # ③ 视图函数：返回值就是响应内容
    return '书签列表'


if __name__ == '__main__':     # ④ 直接运行本文件时才启动开发服务器
    app.run(debug=True)
```

执行 `python app.py`，浏览器打开 `http://127.0.0.1:5000`。

| 组成 | 作用 |
|---|---|
| ① 应用实例 | `__name__` 让 Flask 找到项目目录 |
| ② 路由 | 装饰器把路径登记给紧跟在它下面的函数 |
| ③ 视图函数 | 它的返回值就是响应内容 |
| ④ 开发服务器 | 默认监听 `127.0.0.1:5000`；放在 `if` 里，被别的文件导入时不启动 |

**观察一**：每访问一次，终端多一行 `"GET / HTTP/1.1" 200`。Flask 先按路径和方法找到路由，再调用视图函数，最后把返回值包装成响应，这一行就是三步走完的记录。

**观察二（调试模式）**：把 `return '书签列表'` 改成 `return title`，保存，刷新浏览器，看到 `NameError` 错误页，终端里这次是 500。看完改回去。

调试模式（`debug=True`）提供自动重载（保存后服务自动重启）和详细错误页。错误页附带的调试器**能在服务器上执行 Python 代码**，所以生产环境必须关闭调试模式，第6章改由环境变量控制。

**同步点 S1a**：浏览器显示「书签列表」，终端有 `"GET / HTTP/1.1" 200`。

### 第二段　添加与编辑（同步点 S1b）

**目的**：用路由把 URL 交给视图函数；用 `methods` 和 `request.method` 让同一个地址分别处理 GET 和 POST；用转换器从 URL 中取出编号并检查。

打开 `docs/接口表.md`：「打开添加表单」与「提交新书签」是同一个地址 `/add` 的两次请求，一次 GET、一次 POST。

第一行改为 `from flask import Flask, request`，在 `index` 下面加两条路由：

```python
@app.route('/add', methods=['GET', 'POST'])
def add_bookmark():
    if request.method == 'POST':
        return '收到新书签'
    return '添加书签的表单'


@app.route('/edit/<int:bookmark_id>', methods=['GET', 'POST'])
def edit_bookmark(bookmark_id):
    if request.method == 'POST':
        return f'收到对书签 {bookmark_id} 的修改'
    return f'编辑书签 {bookmark_id} 的表单'
```

**新路由写在哪里**：写在 `if __name__ == '__main__':` 上面。`@app.route()` 是在文件从上往下执行时往路由映射表里登记一行；`app.run()` 启动服务器后一直不返回，写在它下面的装饰器执行不到，那条路由没有登记，访问得到 404，代码本身却看不出错。

**动态路由**：尖括号标出 URL 中的可变部分，Flask 把它取出来，作为**同名参数**传给视图函数。`<int:...>` 还会检查：转不成整数就直接返回 404，视图函数不会被调用。

**验证**：浏览器访问 `/add` 得到 GET 分支。浏览器地址栏只能发 GET，测 POST 要另开一个终端用 curl：

```bash
curl -i -X POST http://127.0.0.1:5000/add
```

**课上预测**：执行下面三条命令之前，先写下各自的状态码和原因（写在纸上或 `~/work/练习/第4讲预测.md`），再运行核对：

```bash

curl -i http://127.0.0.1:5000/edit/abc
curl -i http://127.0.0.1:5000/Edit/7
```

**同步点 S1b**：`/edit/abc` 得到 404；`curl -i -X POST .../add` 得到「收到新书签」。

### 第三段　删除与健康检查（同步点 S1）

**目的**：用方法限定挡住会修改数据的 GET 请求；观察视图函数的返回值怎样变成响应。

接着加两条路由：

```python
@app.route('/delete/<int:bookmark_id>', methods=['POST'])
def delete_bookmark(bookmark_id):
    return f'删除书签 {bookmark_id}'


@app.route('/health')
def health():
    return {'status': 'healthy'}, 200
```

`/health` 是健康检查，云平台靠它判断应用是否在正常运行（第6章容器、第8章监控）。

**课上预测**：先写下预测，再运行：浏览器地址栏访问 `http://127.0.0.1:5000/delete/1` 得到什么？`curl -i http://127.0.0.1:5000/health` 响应头里的 Content-Type 是什么？

两条结论：

- 请求的方法不在 `methods` 里时，Flask 返回 **405**，响应头 `Allow` 列出允许的方法。删除只收 POST，地址栏、预加载、爬虫、误点发出的 GET 都删不了数据。
- Flask 按返回值的类型生成响应：

  | 返回值 | 状态码 | Content-Type |
  |---|---|---|
  | `return '书签列表'` | 200 | `text/html` |
  | `return {'status': 'healthy'}` | 200 | `application/json` |
  | `return {'id': 1}, 201` | 201 | `application/json` |

在 `if __name__ == '__main__':` 上面加一行注释，标出拓展的位置：

```python
# ===== 拓展写在这里：不改上面五条路由，新路由都放在这一行和 if 之间 =====
```

**同步点 S1**：`curl -i http://127.0.0.1:5000/delete/1` 得到 405，响应头有 `Allow: POST, OPTIONS`；`git log --oneline` 看得到「S1: 路由骨架」。

此时的 5 条路由与接口表的对应：

| 接口表中的操作 | 方法 | URL | 视图函数名 |
|---|---|---|---|
| 查看列表 | GET | `/` | `index` |
| 打开添加表单、提交新书签 | GET、POST | `/add` | `add_bookmark` |
| 打开编辑表单、提交修改 | GET、POST | `/edit/<int:bookmark_id>` | `edit_bookmark` |
| 删除 | POST | `/delete/<int:bookmark_id>` | `delete_bookmark` |
| 健康检查 | GET | `/health` | `health` |

视图函数名不要改：第5讲的 `url_for` 和第7讲的测试都按这些名字引用。

| E4 | 四级 | `/routes`：以 JSON 列出应用里所有路由的路径、允许的方法、视图函数名 | 同上 |

### 验证

| 编号 | 命令 | 应得到 |
|---|---|---|
| E1 | `curl -i http://127.0.0.1:5000/about` | 200，`text/html` |
| E2 | `curl -i http://127.0.0.1:5000/version` | 200，`application/json` |

## 常见问题

遇到报错或结果与预期不符时，先在下表中查找。

| 现象 | 原因 | 处理 |
|---|---|---|
| `No module named 'flask'` | 虚拟环境未激活 | 在 `~/work/cloud-bookmark` 下执行 `source ../venv/bin/activate`，提示符前应出现 `(venv)` |
| `Address already in use` | 5000 端口被另一个应用占用 | 在运行那个应用的终端按 Ctrl+C |
| 新加的路由访问得到 404，代码看不出错 | 路由写在了 `if __name__ == '__main__':` 下面 | 把路由移到它的上面 |
| 保存后刷新浏览器，页面没有变化 | 代码有语法错误，自动重载失败 | 查看运行应用的终端里的报错，改正后重新执行 `python app.py` |
| 改成 `return title` 后服务停止，浏览器没有错误页 | 写成了语法错误（如引号未配对） | `title` 不加引号：要制造的是运行时错误 |
| `NameError: name 'request' is not defined` | 第一行没有导入 `request` | 改为 `from flask import Flask, request` |
| 在浏览器中测试 POST 分支，看到的总是 GET 的结果 | 浏览器地址栏只能发出 GET 请求 | 用 `curl -X POST` 测试 |
| 浏览器访问 `/delete/1` 得到 405 | 正确结果：删除只接受 POST | 无需处理 |
| E4 访问 `/routes` 得到 500，报 `not JSON serializable` | 字典里放了集合（`rule.methods`），集合不能直接转成 JSON | 先 `sorted(...)` 转成列表 |
| 复制检查点后 `git status` 显示 `app.py` 被修改 | 正常：检查点替换了你的文件 | 跟完本段后照常提交 |
| `git pull` 课程仓库时报冲突 | 直接在课程仓库里修改了文件 | 在课程仓库执行 `git checkout .` 放弃修改；以后先复制到 `~/work` 再改 |
| `pip freeze` 列出很多依赖 | 共用的虚拟环境里装过其他包 | `requirements.txt` 只保留 Flask 及其依赖：blinker、click、itsdangerous、Jinja2、MarkupSafe、Werkzeug |
